# OCEAN-X Data Guide

This document explains every dataset the OCEAN-X (OceanLens) backend depends on,
which files are committed to Git, which stay local, and how to bring a fresh
clone to a fully working state.

Large scientific datasets are **never committed to Git**. A fresh clone contains
all code, all small metadata, and the full test suite in a passing state — the
multi-gigabyte scientific source data is installed separately.

---

## Quick start for a new developer

```bash
git clone <repo-url> && cd <repo>

# Backend
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Run the test suite (works WITHOUT the large datasets — see "Tests" below)
python -m pytest tests/

# Check which datasets are present/missing on your machine
cd ..
python scripts/check-data.py            # preflight: AVAILABLE / MISSING / INVALID / OPTIONAL

# Install the missing scientific data
python scripts/setup-data.py             # status + instructions
python scripts/setup-data.py --download  # downloads the HYCOM source (~9.85 GB, asks first)
python scripts/setup-data.py --process   # regenerates the processed surface NetCDF from it
python scripts/check-data.py             # should now report required data available: YES
```

## Classification

- **A. Repository data (committed):** IBTrACS CSV, Argo processed/raw JSON,
  HYCOM metadata JSON, provenance docs (`backend/data/metadata/`), the test
  fixtures, and `data/manifest.json`.
- **B. Local scientific data (never committed):** the 9.85 GB
  `RSMC_hycom_20260908.nc` INCOIS HYCOM source file.
- **C. Generated data (never committed):** `incois_hycom_bob_surface.nc`
  (regenerated from B via the extractor script).
- **D. Optional/demo data:** the raw Argo ingestion snapshot; the synthetic
  test fixtures (demo of the schema only — **not** scientific observations).

## Why a dataset may be absent after cloning

GitHub is not suitable for multi-gigabyte scientific files, and scientific
source data must remain unmodified. Therefore `HYCOM_RSMC_RAW` and
`HYCOM_BOB_SURFACE` are covered by `.gitignore` and exist only on machines
where they were downloaded/generated. The application degrades gracefully:
endpoints that need them return explicit
`NO_REAL_MODEL_DATA` / `SIMULATED` statuses instead of crashing, and
`/status` reports the current mode.

## Path configuration

All backend data paths are project-relative by default. If your data lives
elsewhere (e.g., the HYCOM file on an external drive), override via
environment variables — see `backend/.env.example`
(`OCEANX_DATA_DIR`, `OCEANX_RAW_HYCOM_FILE`, `OCEANX_PROCESSED_OCEAN_FILE`, ...).
No machine-specific absolute paths are required anywhere in the code.

## Preflight checker

```bash
python scripts/check-data.py            # human-readable table
python scripts/check-data.py --verbose  # + schema/size details per dataset
python scripts/check-data.py --json     # machine-readable (CI-friendly)
```

Statuses: `AVAILABLE`, `MISSING`, `INVALID` (exists but wrong size/schema),
`OPTIONAL`. Exit code 0 when all **required** datasets are available; missing
optional datasets never fail the check. For NetCDF files the checker lazily
opens the dataset and verifies expected coordinates/variables
(`TIME/DEPTH/LAT/LON`, `UVEL/VVEL/TEMP/SALN/SSH/TCHP/MLD`) without loading
the data into memory.

## Installing data

```bash
python scripts/setup-data.py             # what is missing + exact instructions
python scripts/setup-data.py --check     # same, exit 1 when required data missing
python scripts/setup-data.py --download  # only datasets with a verified public source
python scripts/setup-data.py --process   # regenerate the processed surface file
```

- **Automatic download** is supported only for `HYCOM_RSMC_RAW` (INCOIS
  THREDDS, ~9.85 GB). The tool always announces the size and asks for
  confirmation before transferring; downloads resume if interrupted.
- **`HYCOM_BOB_SURFACE`** is generated locally from the raw file — there is
  no download URL because the file is a project-derived product.
- **IBTrACS** and **Argo** processed data are already committed; to refresh
  them from their providers see the scripts in `backend/scripts/`
  (`process_argo_bob.py`) and NOAA NCEI for IBTrACS.

## Tests with and without production data

`backend/tests/conftest.py` enforces the following policy:

1. **Unit/API tests** (`test_api.py`, `test_argo.py`) run against the **real
   production datasets when installed**. When the HYCOM NetCDFs are absent,
   the conftest binds the dataset paths to the committed **synthetic
   schema-compatible fixtures** and prints a loud banner announcing this.
   The fixtures contain constant placeholder values; they exist purely to
   exercise code paths, API contracts and schema handling. Assertions are
   identical in both modes.
2. **Real-data integration tests** (`test_integration_hycom.py`, marked
   `@pytest.mark.requires_real_hycom`) never use fixtures. They are **skipped
   with an explicit installation message** when the production data is absent
   and run automatically once it is installed.

Run only the fixture-safe suite: `python -m pytest tests/ -m "not requires_real_hycom"`.

## Provenance & scientific integrity caveats

- IBTrACS is real best-track observation data from NOAA NCEI (v04r01).
- The HYCOM fields are real INCOIS RSMC HYCOM model output; the raw file must
  never be modified, and the processed file is a regional surface extraction
  (Bay of Bengal, 5–25°N / 80–100°E) that preserves source values.
- The committed Argo profiles carry the status label
  `REAL SOURCE — INGESTION PENDING`; see
  `backend/scripts/process_argo_bob.py` for how they were curated from GDAC.
- The files under `backend/tests/fixtures/` are **SYNTHETIC TEST FIXTURES**,
  not real observations. They must never be presented as scientific results
  or substituted for production data at runtime.
- `backend/data/metadata/ibtracs.md` documents the IBTrACS variables and units.
